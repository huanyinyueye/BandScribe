# Roselia 轉譜實測

環境：Windows、RTX 4070 12 GB；BandScribe 基準版本 `8d032ba`。原始音訊和參考譜由使用者提供，未放進版本庫。分數的吉他音軌合併後，同一時間、同一音高的重複音符只計一次；音符指標為音高與起音均匹配、容許 50 ms 的 precision / recall / F1。參考譜是人工譜，不代表所有實際演奏的音符都已標註。

## 目前結果（給使用者）

以目前預設流程（`balanced`、Drop D、只轉吉他；MuScriptor medium（含音高位移集成與強力和弦規則）+ Basic Pitch）完整重跑兩首，輸出的 `.gp` 經 alphaTab 回讀驗證，與參考 GP 的吉他音符比較：

| 曲目 | 一開始的 GP | 目前的 GP | 目前的原始辨識（寫譜前） |
|---|---:|---:|---:|
| Ringing Bloom | 0.099 | **0.802** | 0.812 |
| Neo-Aspect | 0.182 | **0.666** | 0.681 |

產物：`out/ringing-guitar-pc/exports/Ringing Bloom.gp`、`out/neo-guitar-pc/exports/09 Neo-Aspect.gp`。吉他辨識（三份音高）每首約 6 分鐘（RTX 4070）。**尚未達到 0.90**，原因見文末「0.90 可行性研究」。GP 只經 alphaTab 回讀驗證，未在 Guitar Pro 8 中開啟。

## Ringing Bloom

完整歌曲：334.888 秒。使用開源 alphaTab 讀取 GP：三軌 Drop D 吉他、一軌 Drop D 貝斯；GP 內嵌 MP3 的 SHA-256 與提供的 MP3 相同。使用 `balanced` 設定執行完整原始流程，當時 MuScriptor 存取尚未開通，實際使用 Basic Pitch 和 ADTOF；分軌使用 BS-RoFormer SW。

以同一批已辨識音符，分別寫出原版及修正後 GP，再讀回 GP 播放事件並與參考譜比較。為公平比較，將匯出譜第 1 小節的起點對齊輸入音訊；這不是額外依分數最佳化的位移。

| 指標 | 原版 GP | 修正後 GP | 辨識結果（未寫譜） |
|---|---:|---:|---:|
| 吉他 note F1 | 0.099 | 0.318 | 0.316 |
| 貝斯 note F1 | 0.065 | 0.344 | 0.342 |

修正後的 GP 回讀為 17,186 個音符、零項目不一致；原版鋼琴軌的八音延音和弦回讀時音高不一致。修正後只表示消除了這些匯出損失，音符辨識本身仍不夠準。未在 Guitar Pro 8 程式中開啟，GP 相容性目前只經 alphaTab 回讀。

相對於分析結果記錄的小節起點，原版 GP 的小節時間誤差中位數為 2.331 秒、最大 3.234 秒；修正後分別為 0.002 秒及 0.023 秒。這項比較對齊第一小節起點，衡量匯出過程的累積誤差，並非與人工參考譜的小節一致度。

產物：`out/ringing-baseline/`（完整原始執行和模型記錄）、`out/reference/ringing-final.gp`（修正後重匯出的完整譜）、`out/reference/ringing.json` 和 `out/reference/ringing-final.json`（開源讀譜工具輸出）。

原版節拍分析得到 187.5 BPM、79 次拍號變動；參考譜為 195 BPM、4/4。試過依高度一致的節拍產生固定網格，雖得到約 195 BPM，但 GP 音符 F1 降至吉他 0.257、貝斯 0.282，因此沒有採用。Basic Pitch 音符提早 40 ms 在此曲上較佳，但尚待第二首曲目驗證，沒有據單曲設定預設。

## Neo-Aspect

完整歌曲以 Basic Pitch / ADTOF 執行完畢，重用 BS-RoFormer SW 分軌；產物在 `out/neo-improved/`。GP 的 13,804 個音符通過 alphaTab 回讀。GP 有三軌 Drop D 吉他，沒有貝斯或鼓的參考軌；不可將缺少參考軌當成零分。GP 內嵌 WAV 比提供的 WAV 短；以音訊互相關量測，提供的 WAV 晚 0.172125 秒，在開頭及 140 秒附近均一致，評分時已補償。

同一批辨識音符以舊版節拍匯出和新版匯出對照，吉他 note F1 由 **0.182 提升至 0.293**；辨識結果本身的 F1 為 0.211。新譜的 BPM 偵測 176.47、參考譜 180，拍號仍有頻繁誤判。評分時同樣以輸出譜第一小節起點對齊音訊，GP 本身沒有內嵌同步音訊。舊版輸出為在同一辨識結果上重跑舊的速度寫入程式，非另一個完整模型推論。

接著重用相同分軌，以 MuScriptor medium + Basic Pitch 執行完整吉他轉譜，使用新的合併策略得到 `out/neo-guitar-final/exports/09 Neo-Aspect.gp`：吉他 GP note F1 **0.516**，alphaTab 讀回的 5,808 個音符一致。這是吉他單軌成果，不是完整樂團總譜。原始辨識比較：Basic Pitch F1 0.213、medium 0.394、兩者所有音符合併 0.365、只保留兩者同意的音符 0.267。新流程保留 medium 找到的音符，剔除僅 Basic Pitch 找到的吉他音符，保留各模型原始結果並記錄剔除原因；若 medium 不可用仍使用 Basic Pitch。量化後的 GP 指標與未量化音符指標不同，不宜直接視為純模型優劣。

對照同一份新樂譜的分析時間，GP5 回讀小節終點誤差中位數 0.003 秒、最大 0.033 秒；MusicXML 分別為 0.000 秒及 0.020 秒。GP5 受弦數限制丟棄 228 個音符，不能視為完整結果。

## 模型短片段對比

Ringing Bloom 第 60–65 秒，輸入相同的分離吉他音軌並以參考吉他音符（40 個）計分：Basic Pitch P/R/F1 = 0.407/0.275/0.328，MuScriptor medium = 0.935/0.725/0.817，MuScriptor large = 0.879/0.725/0.795。相同 50 ms 容許值；Basic Pitch 取自整曲推論，MuScriptor 使用單獨 5 秒片段，因此片段邊界可能造成差異。medium 推論約 8.6 秒，large 約 370 秒（均不含模型載入），顯卡當時有其他工作，並非獨佔效能測試。這不足以代表兩首整曲或預測其他樂器表現。

已下載 large 權重做獨立試驗；BandScribe 原有介面仍只支援 medium，並未把此短片段的結果當作足夠證據修改模型預設。MR-MT3 在相同 5 秒分軌上的音符 F1 為 0.538（P 0.472、R 0.625；53 個音），低於 medium 的 0.817；修正上游套件與 Transformers 版本不相容後，以 CUDA 成功執行。

Neo-Aspect 第 60–75 秒，同一分離吉他音軌、266 個參考音符：Basic Pitch F1 0.138，medium F1 0.427，large F1 **0.220**（P 0.182、R 0.278）。large 推論 15 秒音訊約耗時 449 秒，受顯卡共用影響，無法視為專屬效能基準；這些短片段是探索結果，不代表其他歌曲或樂器。

### Large 與 medium 延伸比較

顯卡負載降低後，同一份 Ringing Bloom 第 60–90 秒分離吉他音軌分別推論，均以 50 ms 起音容差對照原 GP 的 562 個去重吉他音符。以下是寫譜前的辨識結果，不是整曲 GP 成績：

| 方法 | Precision | Recall | note F1 |
|---|---:|---:|---:|
| medium | 0.732 | 0.733 | 0.732 |
| large | 0.763 | 0.795 | 0.779 |
| 聯集合併，共同音符採 large 時間 | 0.732 | 0.852 | 0.788 |
| 交集，共同音符採 large 時間 | 0.800 | 0.705 | 0.749 |

本次 medium 與 large 模型載入後推論分別約 31.8 秒和 335.7 秒；Windows 顯卡仍有其他常駐程序，非隔離效能基準。large 在此 30 秒片段優於 medium，而聯集可略增 F1，但產生更多錯音。Neo 第 60–75 秒相同方法的聯集 F1 為 0.219，低於 medium 的 0.427，因此不能把這種合併方式直接套用整曲或兩首歌。

時間診斷：將 Neo 的兩種模型預測音符都提前 50 ms，medium F1 由 0.427 升至 0.732，large 由 0.220 升至 0.693；這個位移是根據該片段參考譜選出，屬參考輔助診斷，不是自動辨識分數。相同提前量用於 Ringing 的另一首曲目，medium 由 0.732 升至 0.761，large 保持 0.779。仍需整曲及其他歌曲驗證時間校正，才可判斷是否應納入預設。兩首都未證明可達 0.95。

資料及重現：`out/reference/ringing-medium-30s.json`、`out/reference/ringing-large-30s.json`、`out/reference/compare_model_sizes.py`、`out/reference/model-size-comparison.json`、`out/reference/diagnose_large_timing.py`。這些實驗檔保留於本機、未納入版本庫。

## 接手後改進（Claude，2026-11-12）

### 1. MuScriptor 起音延遲校正（30 ms）

MuScriptor 的有音高樂器起音系統性偏晚。整曲原始音符 F1 對校正量（音符已經過相同分軌與合併流程）：

| 提前量 | Neo-Aspect | Ringing Bloom | 平均 |
|---|---:|---:|---:|
| 0 ms | 0.386 | 0.691 | 0.539 |
| 20 ms | 0.567 | **0.749** | 0.658 |
| 30 ms | 0.588 | 0.747 | **0.668** |
| 50 ms | **0.596** | 0.704 | 0.650 |

雙向驗證：以 Neo 選出的 50 ms 用在 Ringing 仍優於不校正（0.691 → 0.704）；以 Ringing 選出的 20 ms 用在 Neo 亦大幅優於不校正（0.386 → 0.567）。兩首的最佳值不同，最後採兩首平均最佳的 30 ms。這個值用到了兩首歌，沒有第三首獨立驗證。鼓沒有證據，不做校正。實作於 `bandscribe/transcription/muscriptor.py`。

### 2. GP 逐拍速度

原匯出每小節只寫一個整數 BPM，小節內的實際拍點不均勻，音符播放位置會偏離數十 ms；50 ms 容差下對分數影響很大。現在每小節記錄拍點的音訊時間（`BarSpec.beat_times`），GP 以 `ratioPosition` 逐拍寫入隱藏的整數速度校正並累計補償誤差，譜面只顯示小節的名目速度。同一批 Neo 音符：每小節單一速度 0.485 → 逐拍 0.567（另一份音符、無弱起小節時為 0.526 → 0.566，證明不再受弱起小節影響）。Ringing（舊 Basic Pitch 音符）吉他 0.318 → 0.319、貝斯 0.344 → 0.354，沒有退步。

### 3. 最終完整 E2E（30 ms + 逐拍速度）

兩首都從頭執行完整流程（重用既有 BS-RoFormer SW 分軌）：

| 曲目 | 原始 MuScriptor P / R / F1 | 匯出 GP P / R / F1 | GP 回讀 |
|---|---|---|---|
| Neo-Aspect | 0.499 / 0.758 / 0.602 | 0.504 / 0.706 / **0.588** | 通過 |
| Ringing Bloom | 0.702 / 0.801 / 0.748 | 0.707 / 0.775 / **0.739** | 通過 |

寫譜損失已從約 0.1 縮小到 0.01–0.015。Ringing 從 0.318 升到 0.739，主因是改用 MuScriptor（原跑使用 Basic Pitch，當時 MuScriptor 尚未開通）。

### 4. 音高位移集成（採用）

把分離後的吉他音軌另外升、降一個半音各辨識一次，音符移回原調後與原調結果合併，三份中至少兩份在同音高、40 ms 內找到才保留，時間優先採原調結果。30 秒片段（兩首皆第 60–90 秒）原始 F1：

| 做法 | Neo | Ringing |
|---|---:|---:|
| 原調 | 0.571 | 0.771 |
| **±1 半音，3 份中 ≥2** | **0.610** | **0.773** |
| ±1 半音，3 份全同意 | 0.596 | 0.727 |
| ±1 半音，任一份 | 0.562 | 0.755 |
| ±2 半音，3 份中 ≥2 | 0.547 | 0.771 |
| ±1、±2 共 5 份，≥3 | 0.600 | 0.764 |

雙向驗證：在任一首選最佳規則，都選中「±1 半音、≥2」，在另一首都不退步。整曲完整重跑（含 30 ms 校正、逐拍速度）：

| 曲目 | 原始 MuScriptor（集成後）P / R / F1 | 匯出 GP P / R / F1 | GP 回讀 |
|---|---|---|---|
| Neo-Aspect | 0.523 / 0.776 / 0.625 | 0.522 / 0.723 / **0.607**（集成前 0.588） | 通過 |
| Ringing Bloom | 0.736 / 0.804 / 0.768 | 0.733 / 0.786 / **0.758**（集成前 0.739） | 通過 |

設定在 `bandscribe/models/defaults.yaml` 的 `transcription.pitch_ensemble`，目前只套用吉他（其他樂器沒有證據），吉他辨識時間約為三倍；各位移的原始結果另存為 `notes/raw_muscriptor_medium_guitar_shift±1.json`。

### 5. 試過但不採用：辨識後過濾錯音（兩首都變差）

| 方法 | Neo F1（基準 0.596） | Ringing F1（基準 0.704） |
|---|---:|---:|
| 和弦最多 4 音，刪最高音 | 0.523 | 0.648 |
| 和弦最多 4 音，優先刪泛音音程 | 0.548 | 0.649 |
| 和弦最多 5 音（泛音優先） | 0.579 | 0.697 |
| 合併同音高重複起音 | 0.261 | 0.193 |

（以 50 ms 校正時的音符評估。）大和弦中的高音多半是對的；模型的音首尾相接，無法藉重疊判斷重複起音。

頻譜八度檢查（以吉他音軌 CQT 比較本音與上下八度能量，判定寫高八度時下移或刪除）：被寫高八度的錯音「本音減下八度」中位數 1.5 / 6.5 dB，正確音 9.6 / 12.6 dB（Neo / Ringing），但分布重疊過大。刪除版 Neo 0.589 → 0.591、Ringing 0.748 → 0.723；只下移版在兩首上沒有任何門檻優於不改。不採用。

### 6. 預處理調查與多視角候選（研究結果，未採用）

公開方法調查：失真還原（Lee et al., DAFx 2024, arXiv 2407.16639）只公開評估程式與示範，無模型權重；主奏／節奏吉他分離只有線上服務（MVSep 等），模型不開放，且需上傳音檔；弦分離（Bastas et al., TASLP 2025）針對單把乾淨吉他。

立體聲：兩首的 BS-RoFormer 吉他音軌左右聲道相關係數僅 0.16（Neo）與 0.05（Ringing），等同兩把吉他分置左右，而流程原本平均成單聲道。30 秒片段 F1（Neo / Ringing）：單聲道 0.571 / 0.771、左 0.585 / 0.739、右 0.626 / 0.798、側（L−R）0.629 / 0.771、左右聯集 0.583 / 0.795。結合音高位移的投票最佳組合平均只比目前規則多 0.013，且需約兩倍運算，不採用。

整曲六視角（單聲道、±1 半音、左、右、側）候選聯集，若完美挑選可得 F1 **0.950 / 0.971**——0.95 所需的音幾乎都在候選中。以另一首歌訓練的挑選器（特徵：哪些視角找到、票數、音高、音長、起音離散、同時音數、八度鄰音、CQT 本音與上下八度能量）：

| 挑選方式 | Neo | Ringing |
|---|---:|---:|
| 目前規則（±1 半音 ≥2 票） | 0.624 | 0.769 |
| logistic，另一首訓練 | 0.649 | 0.744 |
| 梯度提升，另一首訓練 | 0.644 | 0.730 |
| 參考：在測試曲上挑最佳門檻（非公平） | 0.650 | 0.779 |

一首進步、一首退步，即使門檻用測試曲調整也只到 0.65 / 0.78：這些音訊特徵本身分不出候選對錯，瓶頸是「挑選」而非「聽到」。未採用。腳本：`stereo_split_experiment.py`、`view_vote_experiment.py`、`learned_selector_experiment.py`、`whole_song_views.py`、`whole_song_selector.py`。

### 為何到不了 0.95

錯誤分類（50 ms 校正時的整曲音符）：

| 錯誤類型 | Neo 錯音 | Ringing 錯音 |
|---|---:|---:|
| 同音高、時間差 150–500 ms | 809 | 330 |
| 同時間、差八度 | 759 | 757 |
| 同音高、時間差 50–150 ms | 264 | 451 |
| 差五度／四度 | 205 | 140 |
| 附近完全沒有參考音 | 3 | 6 |

- 幾乎沒有「憑空產生」的音。Neo 809 個時間錯誤中，666 個是參考譜在該處寫著延長音，模型卻每約 0.17 秒（176 BPM 的八分音符）重新起音。這很可能是吉他手實際在刷八分音符、譜面簡化成長音；人工譜不是逐音的真實答案，這部分無法以模型修正得分。（2026-11-13 更正：這個推測不成立，參考譜是對的，是模型多寫了起音，見文末「0.90 可行性研究」。）
- 八度錯誤在 Ringing 偏向模型寫高八度（892 對 204），在 Neo 上下對稱（479 對 443），單一規則無法同時適用兩首。
- 參考 GP 為三軌吉他合併，雙吉他疊奏的音在分離後的單一吉他音軌中難以完整分辨。

剩下的方向需要更多資料：以 GOAT、SynthTab、EGDB 等公開的成對資料微調 MuScriptor（單吉他錄音，與樂團失真吉他分軌有落差），或使用者提供更多附同步音訊的 GP。2026 年的新模型 Harmonica（不分樂器）與 TART（吉他 TAB、含技巧）尚未找到公開權重，無法實測。

實驗腳本（本機、未納入版本庫）：`out/reference/false_note_features.py`、`chord_cap_experiment.py`、`error_kinds.py`、`reattack_experiment.py`、`per_beat_tempo_experiment.py`、`ringing_per_beat_experiment.py`、`pickup_bar_experiment.py`、`neo_fixed_shift_experiment.py`、`spectral_octave_check.py`、`octave_fix_cv.py`、`pitch_tta_experiment.py`。

## 0.90 可行性研究（Claude，2026-11-13）

問題：能不能找到一套方法讓吉他 note F1 到 0.90。結論：**以 MuScriptor 的輸出再做任何後處理都到不了 0.90**；找到一條兩首通用的規則並已採用（匯出的 GP：Neo 0.607 → 0.666、Ringing 0.758 → 0.802），其餘九種做法實測無效。以下數字除非另註，都是整曲、寫譜前的原始音符，對照參考 GP。

### 重新診斷：節奏大致對，錯在和弦內容與「延音被重新起音」

把同時起音的音併成一個「事件」來看（單聲道 MuScriptor）：

| 指標 | Neo-Aspect | Ringing Bloom |
|---|---:|---:|
| 事件（有沒有起音）F1 | 0.898 | 0.937 |
| 對上的事件中，和弦內容完全相同 | 201 / 1,153 | 207 / 1,364 |
| 只看起音不看音高的 note F1 | 0.691 | 0.806 |

錯音依成因分類（單聲道、每個錯音只歸一類）：

| 多出的音 | Neo | Ringing |
|---|---:|---:|
| 強力和弦（根音＋五度）上多寫一個高八度根音 | 389 | 820 |
| 參考譜是延音，模型重新起音 | 854 | 208 |
| 上列兩者同時（延音和弦的高八度） | 403 | 31 |
| 起音時間差 50–130 ms | 230 | 85 |
| 其他八度、五度或無關的音 | 819 | 611 |

| 漏掉的音 | Neo | Ringing |
|---|---:|---:|
| 參考譜重新起音，模型寫成一個長音 | 262 | 581 |
| 模型寫在另一個八度 | 249 | 202 |
| 起音時間差 50–130 ms | 131 | 106 |
| 該時間有事件但缺這個音／完全沒有事件 | 215 | 138 |

兩點更正先前的結論：

- **「譜面把八分音符簡化成長音」不成立。** 以 23 ms 窗、2.9 ms 步長量吉他分軌 350–2,000 Hz 的頻譜增量：參考譜低音和弦起音處（不含與主奏同時的起音）的中位數是 0.80（Neo）／0.56（Ringing），參考譜寫延音的八分音符位置是 0.43／0.42，兩首歌幾乎相同（單一特徵 AUC 0.85／0.82）。延音處沒有撥弦的跡象，是模型多寫。典型情況：節奏吉他按著和弦不動、主奏吉他彈八分音符，模型把正在響的和弦在每個主奏起音處整組重寫一次；Ringing 則相反，常把連續刷弦併成長音。
- **八度錯誤不是對稱的雜訊。** 最大宗是兩首一致的「根音＋五度上再加高八度根音」。

### 採用：強力和弦寫成根音＋五度

一個和弦的最低音同時有五度和高八度時，去掉高八度（八度雙音沒有五度，不受影響）。實作在 `bandscribe/transcription/power_chords.py`，設定為 `transcription.power_chord_families`（預設只套吉他；設成 `[]` 關閉），被去掉的音另存 `notes/dropped_power_chord_octave_guitar.json`。

| 規則變體（接在音高位移集成之後） | Neo | Ringing |
|---|---:|---:|
| 不處理 | 0.625 | 0.768 |
| **根音是和弦最低音才去掉（採用）** | **0.681** | **0.812** |
| 任何音只要下方有五度與八度就去掉 | 0.655 | 0.798 |
| 同上，但上方還有八度時保留 | 0.645 | 0.791 |
| 最低音且上方沒有八度 | 0.673 | 0.804 |

四個變體在兩首歌上的排名相同，所以用任一首選都會選到同一條。限制：這是記譜慣例（三弦強力和弦也被寫成兩音），證據只有同一來源的兩份譜。

兩首從頭執行完整流程（重用既有分軌；`balanced`、Drop D、只轉吉他）：

| 曲目 | 原始 MuScriptor（集成＋規則）P / R / F1 | 匯出 GP P / R / F1 | 去掉的音 | GP 回讀 |
|---|---|---|---:|---|
| Neo-Aspect | 0.611 / 0.770 / 0.681 | 0.606 / 0.738 / **0.666**（規則前 0.607） | 799 | 通過 |
| Ringing Bloom | 0.858 / 0.771 / 0.812 | 0.853 / 0.756 / **0.802**（規則前 0.758） | 1,003 | 通過 |

產物：`out/neo-guitar-pc/exports/09 Neo-Aspect.gp`、`out/ringing-guitar-pc/exports/Ringing Bloom.gp`。吉他辨識耗時 332／364 秒。GP 只經 alphaTab 回讀，未在 Guitar Pro 8 開啟。

### 試過但無效

| 做法 | 結果 |
|---|---|
| 以和弦結構為特徵的挑選器（六視角候選；音程關係、前後同音、和弦大小等），一首訓練另一首測 | Neo 0.699、Ringing 0.715（Ringing 低於現行 0.768）。用同一首歌的答案分段訓練也只有 0.74／0.85 |
| 上述挑選器再加撥弦證據（分頻頻譜增量、依音高的諧波梳狀增量） | Neo 0.698、Ringing 0.730 |
| 判斷「主奏起音時低音和弦有沒有重刷」的訊號特徵（頻譜增量、相位偏移，排除主奏諧波） | AUC 0.60–0.77，不足以用 |
| 低通／高通濾波後再辨識（60–100 秒） | 都不如不濾波（0.542／0.782）：低通 300 Hz 無輸出，低通 500／800 Hz 0.07–0.47，高通 250 Hz 0.420／0.779，高通 500 Hz 0.229／0.521 |
| 把主奏的諧波從分軌挖掉再辨識 | 輸出只剩 138／238 個音（原 923／883） |
| 不限制樂器、或直接辨識混音 | 60–100 秒：Neo 0.498–0.532（基準 0.542）、Ringing 0.587–0.798（基準 0.782；只允許失真吉他一類時 0.798，但 Neo 降到 0.532）。多寫起音的數量沒有減少 |
| MuScriptor 的資料集風格條件（0–2） | Neo 60–100 秒：0.543／0.437／0.533，無改善（基準 0.542）；Ringing 未測 |
| beam search 4、條件強化 1.5／2 | 60–100 秒：beam 4 為 +0.015／+0.016（耗時未量測，未採用）；條件強化 1.5 為 +0.011／−0.007，2 為 +0.051／−0.038 |
| 主奏八度雙音補上高音、長音拆回連續刷弦 | 補高音：需其他視角佐證時 +0.009／+0.003 以內，不需佐證時變差（0.633／0.762）。拆長音：+0.005／+0.004，補進去的音約一半是對的 |

多寫的起音在所有設定下數量幾乎不變（Neo 60–100 秒：218–351 個），表示這是模型本身的判斷，不是輸入或解碼方式造成的。

### 上限：為什麼後處理到不了 0.90

在已採用的輸出上，逐項假設「完美解決」並累加：

| 假設 | Neo | Ringing |
|---|---:|---:|
| 目前（集成＋強力和弦規則） | 0.681 | 0.812 |
| ＋延音不再被重新起音 | 0.765 | 0.826 |
| ＋被併掉的重複起音全部還原 | 0.801 | 0.887 |
| ＋起音時間差 50–130 ms 的音全部校正 | 0.822 | 0.897 |
| ＋八度錯誤全部校正 | 0.834 | 0.905 |

要到 0.90，「延音還是重刷」必須幾乎全對，而這個判斷目前只能由辨識模型本身來做：手工特徵最多 AUC 0.77，挑選器跨歌會學到相反的習慣（Neo 的主奏起音處低音和弦 432 次重刷、368 次延音；Ringing 是 735 對 27）。

剩下唯一有機會的方向是讓模型學會這件事：用同類型（雙失真吉他）的「音訊＋GP」微調 MuScriptor。安裝的套件只有推論程式，沒有把音符編成訓練序列的部分，需要自己補上編碼與訓練迴圈；目前只有兩首歌，能做的驗證是「用一首微調、在另一首測」。這項尚未動工。

實驗腳本（本機、未納入版本庫）：`out/research90/`（`diag2.py`、`tax.py`、`attack_evidence.py`、`restrike.py`、`sel2.py`、`rules.py`、`ceilings.py`、`band_views.py`、`cond_views.py`、`nolead.py`、`knobs.py`、`dyad.py`、`gapfill.py`）。

設定同 Neo／Ringing（`balanced`、Drop D、只做吉他、音高集成＋強力和弦規則），腳本 `out/newsongs/run.py`；評分 `benchmarks/score_vs_gp.py`，分析 `out/newsongs/{pitchdiff,where,fair}.py`。

| 歌 | 參考譜 | 吉他 note F1 | P | R | 起音 F1 |
|---|---|---:|---:|---:|---:|
| Neo-Aspect | 4 軌 | 0.666 | | | |

- **Sing Alive 最後一段轉調，參考譜沒寫**：240 秒以後，起音對上的音幾乎全是「輸出比譜高半音」（每 15 秒 230–253 個）。錄音升了半音，GP 照原調寫。把譜在 240 秒後升半音再比，F1 0.500 → 0.656，與 Neo 同級。
- **Song I am 的參考譜只寫一把吉他**（使用者確認）：GP 只有 `Gt-1`，錄音裡另一把吉他沒寫，所以輸出音數是譜的兩倍（3,934 對 1,868），precision 0.37 和 F1 都不能拿來比。15 s、105 s、165–225 s 幾段起音對得上但音高幾乎都不同，應是那幾段兩把吉他彈不同的東西，輸出偏向另一把。這首只看 recall：0.774。
