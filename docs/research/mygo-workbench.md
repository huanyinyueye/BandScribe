# Guitar workbench: reference and integration notes

Question: How can BandScribe retain its local transcription while adopting the review workflow of Bass Harmony Workbench in a MyGo desktop application?

## Findings

- [Bass Harmony Workbench](https://github.com/ntustsvgrandmaster/bass-workbench/blob/main/source/README.md) centers on an audio recording and score, with a fixed transport, variable playback speed, A–B loops, measure navigation and manual score-to-audio alignment. Its timing map uses ordered anchors and piecewise linear interpolation; analysis evidence and locked human annotations are kept separately. It explicitly does not implement whole-song automatic transcription or a full note editor.
- [TimelineAlignment.swift](https://github.com/ntustsvgrandmaster/bass-workbench/blob/main/source/app/TimelineAlignment.swift) validates increasing beats and times and separates alignment anchors from playback loop points. It warns that automatically predicted times are not measured alignment evidence.
- [MyGo getting started](https://mygo.run/docs/getting-started) describes Go desktop windows with either native UI or a system webview, and requires Go 1.27 or later. Its web frontend can reuse a Vite frontend. [Architecture](https://mygo.run/docs/architecture) identifies WebView2 on Windows and typed Go-to-frontend bindings.
- [Guitar Pro's main screen](https://www.guitar-pro.com/docs/gp8/basics/first-steps/main-screen) keeps playback in a top toolbar, editing tools beside the central score, and track navigation in a global view. Its [audio track](https://www.guitar-pro.com/docs/gp8/audio/backing-track) shows waveform, bar grid and sync points together; playback follows a linear audio timeline rather than score repeats.
- BandScribe's `docs/INTERFACES.md` documents an existing Python pipeline with local separation, beat tracking, transcription, guitar fingering and `.gp` export. `PROGRESS.md` records that its example guitar and bass transcribers agreed on only about 22–24% of notes; the generated score needs human review. The current score view can seek original audio by clicking a beat but has no persistent alignment editor or note correction workflow.

## Implications

Retain the existing Python pipeline and output as the initial suggestion; host the existing web application in MyGo while adding a single guitar-focused workspace. A practical sequence is import and automatic transcription, choose guitar track, align score with audio through offset and ordered anchors, review measures with waveform and loop/slow playback, correct and save notes, then export the corrected score. Keep original output, generated evidence and human corrections distinct; reanalysis must not silently overwrite corrections. Existing projects and exports should remain accessible.

The reference's pitch-energy display is evidence, not a ground-truth pitch detector. Neither the reference nor current BandScribe measurements establish that the proposed combined workflow improves transcription accuracy; this needs evaluation on real guitar recordings. Packaging the Python environment, model weights and subprocess lifecycle for a distributable MyGo application is a separate implementation concern, not a capability established by the MyGo documentation.

## Model selection

- [Basic Pitch](https://github.com/spotify/basic-pitch) is a lightweight instrument-agnostic model that supports ONNX and works best on one instrument at a time. BandScribe's `BENCHMARKS.md` measures it as fast on CPU, but substantially worse than MuScriptor on the measured separated full-band guitar.
- The [TART research paper](https://arxiv.org/html/2510.02597v1) reports a guitar-specific multi-stage system and preliminary results, but describes the work as ongoing. Its reported data are not a comparable evaluation on this user's separated songs; the paper alone does not establish an available, smaller deployable model or an improvement here.
- In `BENCHMARKS.md`, the best measured choice depends on the input: on clean GuitarSet the agreed subset scores 0.850 F1, while on one full-band song MuScriptor alone scores 0.723 against 0.320 for Basic Pitch. A small model cannot be called best without comparing usable checkpoints on the same held-out recordings. Existing guitar code already avoids Basic Pitch-only notes when MuScriptor is present; both adapters are selectable.
- Local inventory on 2026-11-22: BS-RoFormer SW checkpoint 667 MiB, SubRoformer 197.8 MiB, Beat This! 77.3 MiB, ADTOF 2.1 MiB; the installed PyTorch `torch/lib` directory alone is about 4.0 GiB. These are disk sizes, not measured executable package sizes. Replacing a Python process with a DLL or Go code cannot remove the weights and inference runtime; compact runtimes and smaller checkpoints must be evaluated separately.
- [muscriptor.cpp](https://github.com/DamRsn/muscriptor.cpp) documents a native ggml implementation and claims matching token streams against PyTorch; Windows CPU and Vulkan are listed as tested. A CPU-only Windows build succeeded here, and its published medium F16 checkpoint was checksum-verified (589.8 MiB). Its bundled 15-second clip had not finished after more than seven minutes on CPU and the run was stopped; no output accuracy or speed was measured. This is not yet integrated or validated against BandScribe's pipeline. [audio.cpp](https://github.com/0xShug0/audio.cpp/blob/main/docs/models/muscriptor.md) documents a separate MuScriptor implementation with a CUDA backend; its performance and compatibility here remain unverified. Its CUDA build was stopped when the user changed priority to interface design.
